## 删除工作区确认弹窗并入弹窗卡片（第三批）

- 目标：`WorkspaceDialogs.tsx` 里的删除确认（title + `description` + 取消/删除工作区）沿用重命名卡片规格。
- 做法：把重命名段的选择器从 `:has(input[class*='_renameInput'])` 扩成 `:is(:has(input[class*='_renameInput']), :has(button[class*='_deleteAction']))`，22 条共享规则一次覆盖两个弹窗；重命名专属（`_body` 的 4px 上边距、`::before` 提示、`input`）保持单选择器；删除专属另起一段（说明行、空 body、状态/错误行、红底按钮 + 暗色）。
- 关键坑（特异性）：`:is()` 取参数里最高的特异性，`:has(input[...])` 是 (0,1,1) 而 `:has([class*=...])` 只有 (0,1,0)，所以删除侧写 `:has([class*='_deleteAction'])` 时按钮规则 (0,5,1) 会输给共享的 outline 规则 (0,5,2)，红底不生效。改成 `:has(button[class*='_deleteAction'])` 后两者同为 (0,5,2)，靠顺序取胜。
- 另一坑：CSS Modules 哈希不一定是后缀，`WorkspaceBrowser.module.css` 的类名是 `FTSSja_deleteAction`（前缀哈希），`[class*='_deleteAction']` 仍能命中，但别假设 `_name_hash` 形式。
- 实测：重命名 420×185 未变（回归通过）；删除 420×156、标题 20/28/600、按钮 62×32 与 104×32、圆角 10、红底 `#EC1313`；暗色卡片 `#232323`、红底 `#F25A5A` 配 `#1A1A1A` 文字（白字对比度仅 2.9:1 故不用）。
- 踩坑记录：中途用 `git checkout -- src/client/styles/base.css` 想撤销脚本误改，结果连未提交的下拉菜单段一起丢了；从 `lib/client.js`（构建产物里的 CSS 字符串）按 `\n` 反转义还原，教训是别对含未提交改动的文件用 checkout。

## 会话搜索框上下边框被裁掉（第六批）

- 现象：侧栏展开的「搜索会话名称」只剩左右两段圆弧，上下边框看不见。
- 根因：皮肤把 `[class*='_sectionHeader']` 压到 30px（`--skin-row-height`），而上游 `.searchExpanded` 是 32px，`.sectionHeader` 带 `overflow: hidden`，于是上下各被切掉 1px —— 正好切掉 1px 边框，只剩圆角。
- 修法：`[class*='_sidebarCol'] [class*='_searchExpanded']` 和其中的 `_searchButton`（该状态上游是 32px）一起取 `--skin-row-height`。实测 192×30，与行带 244..274 完全重合。
- 顺带发现死代码：`base.css` 的 `:root` 里写着 `--dsw-radius-sm/md: 16px`，但 ui-theme 把整套别名 token 以**行内样式**写在 `<body>` 上，比 `:root` 更近，所以组件读到的始终是 `theme.ts` 的 8/12（实测 `document.documentElement` 16px、`body` 8/12）。两行已删；弹窗/菜单用字面 16px，其余控件维持 8/12，视觉无变化。
- 排查坑：`getComputedStyle().borderRadius` 在 32px 高 + 16px 圆角时返回 16px，改成 30px 高后返回 12px，一度以为 token 变了；其实是先量到了 html 层的值（那时 body 行内样式还没写入/被覆盖），后来一次性打印 html/body/#root 三个作用域才看清。
- 验证：新增 `scripts/shot-search.mjs`（展开搜索框 → 截图整窗 + 局部，回读 `header/field/input/clear/magnifier` 几何并给出 `fitsBand` 布尔）。写的时候踩了一个自己挖的坑：`fitsBand` 里误用了外层 DOM 元素变量（`field.h` 为 undefined → NaN → false），改成先算 `headerBox/fieldBox` 再比较。

- 影响面：sm 原来是 8px（图标按钮、输入框等），现在全变 16px；侧栏视觉不变（本来就是 16），变化在 composer、portal 到 `<body>` 的菜单、右侧面板。暗色同值，无需单独分支。

## 搜索框边框消失 + 宽度撑满（第八批）

- 现象：展开的「搜索会话名称」上下边框整条不见，只剩左右两段圆弧（第六批修过，但那次改动后来从 base.css 里丢了，源码里已无 `_searchExpanded` 规则）。
- 根因一（边框）：`.searchExpanded` 上游是 32px 高，皮肤把 `.sectionHeader` 压到 30px 且它带 `overflow: hidden`。2px 溢出上下各 1px，两条水平边框正好落在裁剪区外，被整条切掉。
- 根因二（宽度）：皮肤给 `[class*='_headerActions']` 加了 `max-width: calc(2*行高+4px)`（0,2,0），而上游 `.headerActionsHidden` 只是单类（0,1,0），被压掉 → 展开搜索时动作簇仍占 64px，`searchSlot`（flex:1）只能分到 192px。字段本身已经是 `width:100%`，是没地方长。
- 修法：
  1. `[class*='_searchExpanded'] { height: var(--skin-row-height) }`，并把其中 `_searchButton` 收到 28（30 高 border-box 的内容高）。
  2. 动作簇的 max-width 加 `:not([class*='_headerActionsHidden'])`，让上游的隐藏态生效（实测 maxW 64px → 0px）。
  3. 展开态 header 的 `padding-inline` 归零，字段从 256 → 264，与 `_projectRow`/`_sessionRow` 的 8..272 完全重合。注意这条必须用 `[class*='_sidebarCol'] [class*='_root']:not([class*='_rail']) [class*='_sectionHeader']:has(...)`（0,5,0）才压得过上游 `.root:not(.rail) .sectionHeader:has(.searchExpanded)`（0,4,0）；短选择器写上去是无声失效。
- 为什么敢归零内边距：header 和 field 都用同一个 `--dsw-radius-md`，30 高时两边都 clamp 到 15，字段边框正好贴着 header 的裁剪弧，实测左右圆角 6x 放大无缺口。
- 验证：`scripts/shot-search.mjs` 浅/深各跑一遍 —— field 8/264/30，fitsBand true，深色边框 `#444`；收起态动作簇仍 64px 两枚 30px 按钮；`host-compat.mjs` 16/16。
- 教训：改上游隐藏态时，别只看"上游有没有这个类"，要量 `maxWidth` —— 皮肤的高特异性单条规则会把整个隐藏态吃掉。
